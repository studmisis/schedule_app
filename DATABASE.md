# Настройка базы данных

Инструкция по настройке PostgreSQL, созданию базы данных и заполнению тестовыми данными для проекта Schedule App.

## 1. Проверка PostgreSQL

Для работы приложения необходимо, чтобы PostgreSQL был установлен и запущен.

По умолчанию приложение подключается к PostgreSQL по адресу `127.0.0.1` и порту `5432`.

Проверить доступность PostgreSQL можно командой:

```bash
pg_isready -h 127.0.0.1 -p 5432
```

Если PostgreSQL работает, появится сообщение:

```text
127.0.0.1:5432 - accepting connections
```

Если появилось сообщение `no response`, проверьте, запущен ли сервер PostgreSQL.

## 2. Настройка переменных окружения

В папке `server` находится файл `.env.example` с примером настроек приложения.

Создайте на его основе файл `.env`.

Откройте `.env` и укажите параметры подключения к базе данных и секретные строки для токенов:

```env
PORT=3000
DB_NAME=schedule
DB_USER=your_login
DB_PASSWORD=your_password
ACCESS_TOKEN_SECRET=your_access_token_secret
REFRESH_TOKEN_SECRET=your_refresh_token_secret
```

Описание переменных:

- `DB_NAME` — название базы данных PostgreSQL.
- `DB_USER` — имя пользователя PostgreSQL.
- `DB_PASSWORD` — пароль пользователя PostgreSQL.
- `ACCESS_TOKEN_SECRET` — секретная строка для access-токенов.
- `REFRESH_TOKEN_SECRET` — секретная строка для refresh-токенов.
- `PORT` — порт, на котором запускается сервер приложения.

Для `ACCESS_TOKEN_SECRET` и `REFRESH_TOKEN_SECRET` можно задать произвольные случайные строки. Они должны отличаться друг от друга. Для реального использования рекомендуется выбирать длинные и непредсказуемые значения.

Значения `DB_USER` и `DB_PASSWORD` должны соответствовать существующему пользователю PostgreSQL.

## 3. Создание базы данных и заполнение таблиц

Для создания базы данных, применения миграций и заполнения таблиц начальными тестовыми данными выполните команду из папки `server`:

```bash
npm run db
```

Команда выполняет следующие действия:

1. Удаляет существующую базу данных.
2. Создаёт базу данных заново.
3. Выполняет миграции, создавая таблицы.
4. Заполняет таблицы начальными тестовыми данными из сидера.

## 4. Структура базы данных

После выполнения миграций в базе данных `schedule` создаются следующие таблицы:

- `Users` — пользователи приложения, их учётные данные и роли.
- `Teachers` — информация о преподавателях, связанная с учётными записями пользователей.
- `Students` — информация о студентах и принадлежности к учебным группам.
- `Groups` — учебные группы.
- `Disciplines` — список учебных дисциплин и назначенных преподавателей.
- `Lessons` — занятия, их даты, время, темы и ссылки.

### Связи между таблицами

- Один пользователь может иметь профиль преподавателя или студента.
- Каждый преподаватель связан с учётной записью в `Users`.
- Каждый студент связан с учётной записью в `Users` и одной учебной группой.
- Одна учебная группа может содержать несколько студентов.
- Один преподаватель может вести несколько дисциплин.
- Каждая дисциплина назначена одному преподавателю.
- Каждое занятие связано с одной дисциплиной, одним преподавателем и одной учебной группой.
- Пользователь, создавший занятие, сохраняется в поле `created_by`.

Таблица `Lessons` содержит следующие основные поля:

- `date` — дата занятия.
- `start_time` — время начала занятия.
- `discipline_id` — идентификатор дисциплины.
- `teacher_id` — идентификатор преподавателя.
- `group_id` — идентификатор учебной группы.
- `created_by` — идентификатор пользователя, создавшего занятие.
- `topic` — тема занятия.
- `join_url` — ссылка для подключения к занятию.
- `recording_url` — ссылка на запись прошедшего занятия.

Поле `recording_url` изначально может быть пустым. После проведения занятия администратор может добавить ссылку на запись.

### Начальные тестовые данные

Сидер, расположенный в папке `server/seeders`, добавляет следующие тестовые данные:

- 1 администратора.
- 3 преподавателей.
- 5 студентов.
- 1 учебную группу.
- 5 дисциплин.
- 5 занятий.

Все пять студентов относятся к одной группе. У каждого преподавателя есть отдельная учётная запись. Преподаватели могут вести несколько дисциплин.

## 5. Проверка получения данных из базы

После создания базы данных и заполнения таблиц тестовыми данными запустите сервер:

```bash
npm run dev
```

Откройте в браузере следующие адреса:

- `http://localhost:3000/api/disciplines` — получение списка дисциплин из таблицы `Disciplines`.
- `http://localhost:3000/api/users` — получение списка пользователей из таблицы `Users`.

Если всё работает корректно и соответствующие маршруты реализованы, в браузере отобразится JSON с данными из соответствующих таблиц.

## 6. Возможные проблемы

### Не удаётся подключиться к PostgreSQL

Убедитесь, что PostgreSQL запущен и доступен на порту `5432`:

```bash
pg_isready -h 127.0.0.1 -p 5432
```

### Ошибка авторизации PostgreSQL

Проверьте значения `DB_USER` и `DB_PASSWORD` в файле `.env`. Они должны соответствовать существующему пользователю PostgreSQL.

### База данных не найдена

Проверьте значение `DB_NAME` в файле `.env`. Убедитесь, что пользователь PostgreSQL имеет необходимые права на создание базы данных.

Для первоначального создания базы данных и заполнения тестовыми данными выполните из папки `server`:

```bash
npm run db
```

**Важно:** команда удаляет существующую базу данных перед созданием новой. Все данные в ней будут потеряны.
